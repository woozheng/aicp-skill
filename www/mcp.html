AICP · 双向 MCP 节点

对外是 MCP Server，对内是 MCP Client —— 一边把能力暴露给 AI 工具，一边把外部工具吸进 AICP。

MCP Server · 向外提供能力 ⇄ MCP Client · 向内吸收能力
As a Server 向外提供能力
AICP doesn't just expose a handful of tool calls — it exposes an entire orchestration-ready engineering runtime. Every backend plugin from apps you've generated, every internal skill you've accumulated, BIO-1's self-orchestration capability, and system-level primitives like files, tasks, and memory — all reachable through five meta-tools. What your AI client gets is a working agent OS, not a pile of scattered APIs.
Endpoint
The MCP server runs as a separate process on port 9100, alongside the HTTP gateway on 9000.
URL
http://127.0.0.1:9100/mcp
Transport
Streamable HTTP — POST
Authorization
Authorization: Bearer <token>
Session
Mcp-Session-Id
In local mode the token is optional. In token / hybrid mode sign a token from the Admin page first.
Exposed tools
Five meta-tools. Everything else is reachable through them — no context explosion.
call_plugin

Call any AICP plugin by its full route. The core of the bridge.

receiver
list_capabilities

Discover what AICP can do — search plugins by keyword or list them all.

optional
get_contract

Get a plugin's parameter contract and usage notes before calling it.

plugin
my_memory

Your experience backpack — stored on the AICP side, survives switching clients.

optional
my_tasks

Your task board — resume, update and close work from any MCP client.

Client setup
Paste into your client's MCP configuration. Replace <token> with the token from the Admin page.
~/.claude.json
{
  "mcpServers": {
    "aicp": {
      "type": "http",
      "url": "http://127.0.0.1:9100/mcp",
      "headers": {
        "Authorization": "Bearer <token>"
      }
    }
  }
}
Claude Code supports type: "http" directly — no bridge needed.
~/.cursor/mcp.json

  "mcpServers": {
    "aicp": {
      "type": "http",
      "url": "http://127.0.0.1:9100/mcp",
      "headers": {
        "Authorization": "Bearer <token>"
      }
    }
  }
}
cline_mcp_settings.json
{
  "mcpServers": {
    "aicp": {
      "type": "streamableHttp",
      "url": "http://127.0.0.1:9100/mcp",
      "disabled": false,
      "headers": {
        "Authorization": "Bearer <token>"
      }
    }
  }
}

Smoke test
Hit the endpoint directly to confirm it answers before blaming the client.
curl
curl -s -X POST http://127.0.0.1:9100/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer <token>" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
You should see call_plugin in result.tools. Health checks live at /health, /ready and /metrics on the same port.
As a Client 向内吸收能力

AICP 本身也是 MCP Client，可以反向接入任意外部 MCP Server。接入后的工具会变成 AICP 体内和内置插件平权的能力，agent 可以直接调用，也能通过 AICP 的 MCP Server 再暴露给上层客户端。

也就是说，AICP 是一个MCP 汇接点：一边接你的 AI 工具（Claude Code / Cursor / Cline …），一边接任意外部 MCP Server，中间由 BIO-1 统一编排。

怎么接入

在控制台把 MCP Server 的信息告诉 BIO-1，它会自动完成注册，无需手动改配置。

"帮我接入这个 MCP Server：
  name: <服务名>
  url: https://
  auth: Bearer <token>"
接入完成后，外部工具以 <server_name>/<tool_name> 的路由出现在系统中，可被 AICP BIO-1 编排，在对话中触发。
